# Provenance Audit, Metadata Migration, and Population Stratification

References: Refs #78; follows ADR-0007, PR #59, PR #68, and [docs/snapshot-manifest.md](../snapshot-manifest.md).
Status: Normative provenance audit for Milestone 2 datasets.
Maintainers: @Lolavine777 (Author), @nairyuuu (Reviewer).

---

## 1. Context and Objective

This audit investigates the provenance metadata, source integrity, and population boundaries for the two primary Milestone 2 datasets: the `SEAMLESS.INTERNAL` Active Directory snapshot and the `evtx_data.csv` candidate telemetry collection.
Prior ingestion artifacts contained placeholder collection timestamps and inferred collector versions that were not grounded in immutable source evidence.
Furthermore, documentation mixed verified local sample sizes with external corpus claims, and referential integrity assertions did not distinguish first-class collected nodes from materialized boundary stubs.
This document establishes auditable claims, defines honest metadata under snapshot manifest schema v1, formalizes the consumer compatibility policy, and tracks snapshot identity migrations.

## 2. Source Metadata Audit

### 2.1. SEAMLESS.INTERNAL Snapshot (`seamless-v1`)

The SEAMLESS snapshot provides the primary synthetic enterprise-scale topology baseline for Milestone 2.

- **Upstream Repository:** `https://github.com/mike-nolan-councilman/Bloodhound_Data`
- **Pinned Commit:** `8c3107421bb910e5e2b4d16631e243ddb0756ca5`
- **Source Archive:** `20210920185958_BloodHound.zip` (268,200 bytes, SHA-256: `b8e9f003dd51a98838be86d8f98b0844a19a7876aad0a81b525f19e110105813`)
- **Extracted Files:** 6 JSON export files (`20210920185958_computers.json`, `domains.json`, `gpos.json`, `groups.json`, `ous.json`, `users.json`), totaling 11,371,828 uncompressed bytes.

The separate [scope identity evidence audit](seamless-scope-identity.md) verified the archive from the pinned upstream commit against its recorded SHA-256. The archive contains exactly the six manifest-covered exports and no supplemental metadata. The Domain export has a DNS name and domain SID but no stable Domain objectGUID; GUID-shaped link references identify GPOs. Under Contract 1.3, the observed Domain SID supplies typed Domain scope. The two unresolved well-known references now resolve to explicit boundary principals under a narrow Windows SID policy. Collection-time provenance is separate: an explicit assumed timestamp resolves time status but does not supply identity scope.

#### Metadata Field Audit

1. **`collected_at` (Previously claimed: `2021-09-20T18:59:58Z`):**
   - The timestamp `20210920185958` matches the filename prefix generated by SharpHound.
   - SharpHound formats export filenames using the local system clock (`DateTime.Now.ToString("yyyyMMddHHmmss")`) of the collection host.
   - The JSON export envelopes contain no timezone offset or UTC declaration.
   - Per [docs/snapshot-manifest.md](../snapshot-manifest.md), filename timestamps must not be interpreted as UTC without explicit timezone evidence.
   - **Finding:** Unverified timezone; the exact UTC collection time is unknown.
   - **Corrected Value:** `null`.

2. **`collector.name` (Claimed: `sharphound`):**
   - The file structure and metadata format match SharpHound export envelopes for BloodHound.
   - **Finding:** Evidenced by generator format and upstream repository documentation.
   - **Corrected Value:** `sharphound`.

3. **`collector.version` (Previously claimed: `3.0`):**
   - In each JSON envelope, the header `meta` block specifies `{"count": ..., "type": ..., "version": 3}`.
   - The `version: 3` field in the BloodHound envelope represents the JSON export schema compatibility version, not the SharpHound collector binary version.
   - The SharpHound collector release version (such as 3.0.x or 3.1.x) is not recorded in the JSON envelope headers.
   - Per [docs/snapshot-manifest.md](../snapshot-manifest.md), export schema version must not be treated as collector version.
   - **Finding:** SharpHound binary version is unrecorded.
   - **Corrected Value:** `null`.

#### Metadata Field Audit

3. **`collector.version` (Previously claimed: `1.0`):**
   - The upstream repository `sbousseaden/EVTX-ATTACK-SAMPLES` does not publish semantic release versions or tags.

## 3. Population Stratification

### 3.1. Telemetry Population: Verified Local Rows vs External Corpus Claims

Historical project documentation referenced 6,432 security events across 11 MITRE ATT&CK tactics, originating from upstream EVTX-ATTACK-SAMPLES literature rather than measured local observations.
Analysis of the verified raw file `data/raw/telemetry/evtx_data.csv` (governed by [telemetry-raw-v1.json](../../data/samples/manifests/telemetry-raw-v1.json)) establishes the true population:

| Metric | Verified Local Subset (`evtx_data.csv`) | External Literature / Corpus Claim | Resolution |
| --- | :---: | :---: | --- |
| Total Events | 4,633 rows | 6,432 events | 4,633 is the exact row count of verified bytes; 6,432 is a historical project claim from upstream literature. |
| ATT&CK Tactics | 8 tactics | 11 tactics | Verified rows map to 8 tactics; 11 tactics is a historical project claim from upstream literature. |
| Distinct Computers | 19 computers | 19 computers | Confirmed across verified rows. |
| Distinct Usernames | 35 user accounts | 35 user accounts | Confirmed across verified rows. |
| Temporal Span | 2017-06-09 19:21:26 to 2021-06-09 05:18:11 | 2017-06-09 to 2021-06-09 | Confirmed by earliest and latest `SystemTime`/`UtcTime` entries measured from verified bytes. |

Reports and exploratory analyses must publish metrics measured strictly on the verified 4,633 rows.
The 6,432 events and 11 tactics figures represent historical project claims from upstream literature and must never be cited as measured local metrics.

### 3.2. SEAMLESS Referential Integrity Stratification

Prior documentation asserted "100% referential integrity" for SEAMLESS without qualifying how dangling references were resolved.
A rigorous accounting separates collected first-class principals from synthesized boundary nodes:

| Entity Resolution Category | Count | Percentage | Rationale |

| Unresolved / Dangling References | 0 | 0.000% | Zero references fail resolution once boundary stubs are materialized. |

Future analyses and reports must present these distinct resolution tiers rather than claiming unqualified 100% internal closure.

## 4. Compatibility and Migration Policy

### 4.1. Manifest Schema v1 Status

Snapshot manifest schema v1 ([docs/snapshot-manifest.md](../snapshot-manifest.md)) already specifies that `collected_at` and `collector.version` accept JSON `null` to represent unknown values.
Validation via `src.data.manifest.validate_manifest` explicitly accepts `null` for both fields.
Consequently:
- This change is a metadata correction within schema version 1.
- No schema version increment (for example to v2) is warranted, because no schema rules or validation invariants were broken or expanded.

### 4.2. Consumer Policy Separation

A critical distinction exists between manifest file verification and downstream graph parsing:

1. **Snapshot Manifest Layer ([src/data/manifest.py](../../src/data/manifest.py)):**
   - Sole responsibility: cryptographic identity and byte-level tamper detection of local directory files.
   - Permits `collected_at: null` and `collector.version: null` when source evidence is missing.

2. **Active Directory Loader Layer ([src/parser/loader.py](../../src/parser/loader.py)):**
   - Implements `ManifestRawDataLoader` per PR #68.
   - Enforces that AD JSON export envelopes have a non-null collection timestamp in order to populate `Provenance.timestamp` required by graph contract 1.0.0.
   - Raises `ManifestError` if an AD snapshot envelope lacks an evidence-backed collection timestamp.

3. **Telemetry Analysis Layer ([scripts/eda_dataset_analysis.py](../../scripts/eda_dataset_analysis.py)):**
   - Telemetry is stored as CSV logs, not Active Directory JSON export envelopes.
   - Telemetry verification uses `src.data.manifest` to ensure byte integrity.
   - Telemetry is analyzed directly from verified bytes and is never routed through `ManifestRawDataLoader`.

### 4.3. Downstream Impact and Owned Follow-up Policy

Setting `collected_at: null` on `seamless-raw-v1.json` accurately reflects the absence of timezone evidence in the raw export.
Because `ManifestRawDataLoader` rejects snapshots with `collected_at: null`, SEAMLESS cannot currently be parsed by `ManifestRawDataLoader`.
This creates an explicit owned follow-up policy decision:
- Owned follow-up task (Issue #91): Define the formal loader time-provenance policy for snapshots with unknown collection timezones (such as an explicit fallback policy, configuration flag, or BadBlood-specific adapter).
- Parser tasks #44/#45 must not implicitly absorb or bypass this loader policy without an approved architectural decision.
- SEAMLESS parser integration is explicitly gated by this resolution, avoiding the injection of unverified timestamps.
